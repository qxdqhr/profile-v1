# 01 · 给前端和移动端开发者的心智模型

把 WordPress 想成：**带后台的服务端渲染 CMS**，主题 ≈ 一套「页面路由 + View」，PHP ≈ 模板里的业务胶水。

## 和你熟悉技术的对照

| 你已会的 | WordPress / Holt 里像什么 |
|----------|---------------------------|
| H5 页面 + CSS | 主题模板输出 HTML；`assets/main.css` 管视觉 |
| JS（页面交互） | `assets/main.js`（入场动画等）；复杂逻辑也可用 WP REST |
| Swift / OC：`UIViewController` + Storyboard/XIB | `front-page.php` / `single-work.php` 等模板 = 不同页面的「控制器+视图」 |
| Swift：`Codable` + API | CPT `work` + `post_meta` = 结构化数据；REST：`/wp-json/wp/v2/work` |
| ArkTS：`@Entry` + 路由表 | **模板层级（Template Hierarchy）**：URL → 自动选哪个 `.php` 文件 |
| App 的 `Info.plist` / 模块入口 | `style.css` 头部声明主题名；`functions.php` = AppDelegate / Ability 生命周期挂钩 |
| CocoaPods / SPM 插件 | WordPress **插件**（Holt 尽量少依赖插件，能力写在主题里） |
| 本地模拟器 | `docker compose -f docker-compose.dev.yml up` |
| TestFlight / 应用商店发布 | 推 `main` → GitHub Actions `deploy-web` → 服务器挂载主题 |

## 三个必须记住的目录

1. **核心**（容器内，一般不改）：`/var/www/html/` 里的 WordPress 本体  
2. **主题（二开主战场）**：`wp-content/themes/holt-portfolio/`  
3. **上传媒体**：`wp-content/uploads/`（封面图等）

> 规则：像改 iOS 业务一样，**改主题 / 数据，不要改 WordPress 核心文件**（升级会被覆盖）。

## 请求怎么变成页面（极简）

```
用户打开 /wp/holt/works/xxx/
  → nginx 转到 wordpress_holt
  → WordPress 查数据库：这是一条 work
  → 模板层级选中 single-work.php
  → PHP 拼 HTML（header + 内容 + footer）
  → 浏览器拿到完整 HTML + 引用 main.css / main.js
```

对比 ArkTS：你写路由表自己配；WP 用**约定文件名**代替路由表（见下一篇模板层级）。

## PHP 你只需要先会这些（够改 Holt）

```php
<?php echo esc_html( $title ); ?>     // 输出文本（要转义，防 XSS）
<?php if ( $x ) : ?> ... <?php endif; ?>
<?php foreach ( $list as $item ) : ?> ... <?php endforeach; ?>
get_header(); get_footer();           // 引入头尾
the_title(); the_content();           // 当前文章字段
get_post_meta( $id, 'bilibili_url', true );  // 自定义字段
```

语法有点像「HTML 里插脚本」——你写过服务端模板或早期 JSP/ASP 会更熟；没有的话，把 `<?php ... ?>` 当成「在 HTML 里调用函数」。

## Holt 站「产品」是什么

- **前台**：音乐作品集（B 站 PV 嵌入、合集筛选、播放量、接单页）  
- **后台**：`/wp/holt/wp-admin/` 管作品、外观自定义、媒体库  
- **数据**：MariaDB 库 `wp_holt`（与主站 Postgres **无关**）
